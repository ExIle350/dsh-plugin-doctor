# dsh-plugin-doctor · 插件体检

> DeepSeek Harness (DSH) 插件健康检查面板
> A plugin health panel for DeepSeek Harness

<br>

## 它解决什么问题

DSH 的插件**挂载失败是静默的**。

一个插件行（loader entry）被禁用、入口文件缺失、`exports["./client"]` 指向的构建产物不存在——这些情况下宿主**不写日志、不报错、不弹窗**。用户看到的现象是：

> 「我装了，也重启了，但什么都没发生。」

更糟的是崩溃场景：某些缺失会让整个 profile 起不来，弹一句 "The application could not start"，错误信息里全是内部堆栈，普通人读不出到底缺了什么。

**这个插件把这三件事摊开在设置里：**

| 面板区块 | 回答的问题 |
|---|---|
| **Loader 行状态** | 我装的插件里，有没有哪一行被禁用了？（只有这一项非空才告警） |
| **Bundles 核对** | 每个包真的装上了吗？入口文件在吗？`exports["./client"]` 指向的产物存在吗？peer 有没有需要自备的？ |
| **路由探活** | 输入任意路径，用当前会话凭据发一次请求：`401` = 该插件已挂载（被鉴权拦住，正常），`404` = 没挂载 |
| **复制诊断 JSON** | 一键拷出完整报告，贴给别人或提 issue |

<br>

## 设计原则

**不喊狼来了。** 宿主自己会关闭大量内置功能（`tool-bash`、`plan-mode`、`tool-web`、各种 compaction 策略等），这些都是**正常状态**。本插件把「用户自己安装的插件被禁用」和「宿主内置功能关闭」严格分开——只有前者标红，后者作为灰色信息折叠显示。

一个把所有异常都涂红的面板，比没有面板更糟：它教会用户忽略红色。

**不假装成功。** 核心数据来自 `ctx.loader.entries()`。若某个宿主版本不提供这个接口，面板会明确显示"读不到 loader 内部"并说明原因，其余区块（bundles 核对、路由探活）继续可用。

<br>

## 安装

```sh
dsh plugin --profile <你的profile名> add dsh-plugin-doctor
```

或从仓库安装：

```sh
dsh plugin --profile <你的profile名> add github:<你的用户名>/dsh-plugin-doctor
```

装完**重启一次 DSH**（托盘完全退出后重新打开），然后打开 **设置 → 插件体检**。

## 权限与副作用

诚实说明本插件的边界：

- **文件系统**：只读。读取 profile 的 `package.json` 与各插件包的 `package.json`，用于核对入口文件与 `exports` 映射。**不写任何文件。**
- **网络**：无出站请求，无遥测，不加载任何外部资源。
- **HTTP 面**：仅注册两个只读路由 `GET /dsh-doctor/report` 与 `GET /dsh-doctor/probe`，均经过宿主的连接鉴权栅栏（未授权返回 401）。不新增监听端口。
- **Shell / 子进程**：不使用 `child_process`。
- **是否需要重启**：安装后需要一次；此后面板每次打开都会重新拉取报告，无需重启。
- **失败影响**：`apply()` 内部任何异常都被捕获并只写一条 warn 日志——本插件不会让宿主起不来。

<br>

## 排查示例

**现象**：装了某插件，界面上没有任何变化。

1. 打开 设置 → 插件体检
2. 看 **Bundles 核对**：那一行是 ✓ 还是 ✗？
   - ✗ `node_modules 里找不到该包目录` → 没装上，或 `link:` 目标被移动过
   - ✗ `exports["./client"] 指向的文件不存在` → **这个最危险**，缺客户端构建产物会让宿主启动即崩
3. 看 **Loader 行状态**：它出现在列表里吗？是不是 ✗（被禁用）？
   - 被禁用且不是你自己关的 → 大概率是该插件补丁里的 `disabled` 条件命中了
4. 用 **路由探活** 输入它的某个路由：
   - `401` → 宿主半侧确实挂载了，问题在浏览器半侧
   - `404` → 宿主半侧根本没起来

<br>

## 开发

```
lib/index.js       Host 半侧：报告生成 + 两个只读路由
lib/client.js      浏览器半侧：设置面板（手写 ModuleLoader bundle，无需构建）
cordis.patch.yml   bundle 层：插入插件行
```

改完 `lib/` 下的文件需要重启 DSH 才会重新加载。

本插件**不需要构建步骤**——`lib/client.js` 是手写的 `window.__ModuleLoader__.load(...)` bundle，直接随包发布。

<br>

## 已知限制

- 依赖宿主的 `ctx.loader.entries()`。这是插件生态里已被使用的公开面，但不是稳定 API 承诺；若未来宿主移除，Loader 区块会降级（其余区块不受影响）。
- 「是否安装」的判定基于 profile `node_modules` 的文件存在性，不执行模块加载，因此无法发现"文件在但运行时报错"的问题——那需要看路由探活。
- 报告里会包含 profile 目录路径。分享 JSON 前留意是否含你不愿暴露的路径。
